# SplitLui Phase 18 — Receipt photos and on-device OCR

## What this adds

- **Add expense**: Take a receipt photo or choose one from Gallery.
- Compress to a JPEG image (5 MiB maximum) before private upload.
- Attempt OCR locally using Google ML Kit. A plausible **TOTAL** or
  **AMOUNT DUE** is suggested only when the amount field is empty.
- The user must check and confirm title, currency, total amount, payer,
  participants and any exchange rate. OCR does not save an expense.
- Works for both ordinary shared expenses and **Common Fund paid** expenses.
- After saving, open expense or Common Fund purchase details to view the
  linked private receipt image through a signed URL (60 second validity).
- If the expense is saved but uploading the photo fails, show a warning
  to avoid duplicate expenses. Retrying attachment after a failed upload
  is a future enhancement along with the offline upload queue.

This feature does **not** yet parse receipt item lines, taxes, dates or
multi-currency hints automatically. The MVP OCR only recognises printed
Latin-script totals; full Thai-script recognition is **not guaranteed**.
No paid third-party AI API is used.

## REQUIRED Supabase SQL migration

Run once in Supabase Dashboard → SQL Editor, after the previous migrations:

    supabase/migrations/20261103_000012_trip_receipts.sql

This creates:
- A **private** `splitlui-receipts` Storage bucket (JPEG, 5 MiB limit).
- `trip_receipts` mapping to either a personal expense or a
  Common Fund expense (never both).
- Storage RLS: group members can view receipts, members upload only
  under their own group/user folder, and unlinked uploads can be
  removed by their original uploader.
- `attach_trip_receipt` RPC, which validates that only the actual
  expense creator or fund-entry recorder can link an uploaded image.

**Do not make the bucket public.** Uploaded files and metadata must
remain accessible only to authenticated group members. Test with a
non-member account to confirm it cannot create signed URLs or view
another group's receipt.

## Flutter dependencies

The PR adds:
- `image_picker`: camera/gallery
- `flutter_image_compress`: JPEG compression
- `google_mlkit_text_recognition`: on-device OCR (Latin script)

Google ML Kit plugin v0.15.x requires Android compileSdk >=35. The
current project sets compileSdk from Flutter; verify that your local
Flutter SDK resolves to at least 35. For iOS in a later phase, confirm
minimum iOS target and add these keys under `ios/Runner/Info.plist`:

    NSCameraUsageDescription
    NSPhotoLibraryUsageDescription

Explain clearly that photos are used to attach travel receipts. Do not
commit autogenerated iOS platform files without checking the project
configuration.

## Build & testing

    git pull origin master
    flutter pub get
    flutter gen-l10n
    flutter analyze
    flutter test test/receipt_capture_test.dart
    flutter build apk --release

1. Apply SQL migration *before* installing the new APK.
2. Create group expense → choose Camera → take photo → see thumbnail.
3. Verify OCR suggests a correct total only when the amount is empty.
4. Change the amount manually; choosing another receipt must not
   overwrite the manually entered amount.
5. Save → open Expense Details → verify the receipt can be viewed.
6. Record an expense paid by Common Fund → verify receipt in fund
   expense details. Ensure it doesn't create an individual split.
7. Verify another group member can view the image and a non-member
   cannot. Check cross-group access and signed URL expiry.
8. Turn off network when uploading: **expense may still have been
   saved**. UI should tell the user not to create duplicate entries.
9. Test in both languages, with dark theme, on smaller screens,
   and when the user cancels the image picker.
